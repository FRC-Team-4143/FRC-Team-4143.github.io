σ (sigma) is how far off you expect a reading to be. Each reading pulls the estimate q ÷ (q + σ) of the way toward it. The 2026 robot uses σ 0.9 for x, y and heading, a 10% pull.

How our cameras find the robot

Three global-shutter cameras face left, right and back. Left and right sit 0.29 m off the floor, the back one 0.54 m. All tilt up 0.17 rad (10°) and see about 1.35 rad (77°) side to side. Because they tilt up, a tag that is too close or too low drops out of view. The hub and trench walls block anything behind them.

An Nvidia Jetson finds AprilTags with a GPU detector at 60 frames a second per camera, solves the robot's pose, and sends it to the roboRIO with the time the picture was taken.

How the Kalman filter blends odometry and vision

Odometry adds up how far the wheels turned, with the gyro giving the heading. Worn treads, carpet seams, wheel scrub, bumps (a 0.29 rad slope) and pushing into walls make it drift. Another robot shoving ours slides the wheels sideways, so odometry never sees it.

The robot runs two estimators. The smooth pose only uses odometry. The field pose also takes camera readings through addVisionMeasurement(pose, timestamp, stdDevs). Each reading pulls it a fraction q ÷ (q + σ) of the way, the WPILib pose estimator's gain. With q 0.1 and σ 0.9 that is 10%. The Computer Vision lesson starts at σ 5.0, a 2% pull, and checks for 0.06 m and 0.017 rad.

The 2026 vision checks, in order
  1. Spin rate over 12.57 rad/s: drop the whole frame. The code compares the signed rate, so only counter-clockwise spins trip it. This lab checks both directions.
  2. Inside our alliance zone (x < 3.963 m, mirrored for red), fewer than 2 tags: skip.
  3. Pose outside the field walls: skip.
  4. Heading more than 6.28 rad from the estimate: skip. That never happens, so this check is off.
  5. Everything else gets σ 0.9, or the focused / not-focused σ in a focus state.
Why each reading is off

Expected error (1σ) = distance error × viewing-angle factor + motion blur + bump tilt. The robot never sees this number. The 2026 code gives every reading the same σ, so a blurry far reading counts as much as a sharp close one.
