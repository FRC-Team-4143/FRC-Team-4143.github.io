State Machine Lab

Drive the 2026 robot's super state machine (RobotContainer) one 20 ms loop at a time. Hold a button to ask for a state, then watch the transition table pick where the robot goes, updateLogic ask each subsystem for a state, and each subsystem's own state machine decide when it gets there.

Walkthrough

     

    The loop

    Loop0
    Time0.00 s
    Speed1×

    Every 20 ms the robot runs this, in this order (MwSuperStateMachine):

    1. robot.handleStateTransition(wanted)
    2. robot.updateLogic() asks each subsystem for a state
    3. each subsystem: handleStateTransition, then updateLogic

    So a subsystem sees the robot's request in the same loop. Press Pause, then Step one loop (N) to run them one loop at a time.

    What the buttons call

    Each button is bound in OI.java. Pressing it asks the robot for a state; letting go asks for DRIVE. The buttons never talk to a subsystem.

    driver_controller_.rightTrigger().whileTrue(    Commands.startEnd(        () -> robot.setWantedState(RobotStates.SHOOT),        () -> robot.setWantedState(RobotStates.DRIVE)));

      Two buttons at once?

      The real OI.java only asks for DRIVE on release if that button's state is still the wanted one, so letting go of Shoot doesn't cancel an Intake you are still holding. This lab does the same.
